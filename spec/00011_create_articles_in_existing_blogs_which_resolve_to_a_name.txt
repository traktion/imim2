As a blog creator
I want to be able to create articles in existing blogs when the blog address is a name
So that I can easily add new pages to my blog

Given the create article form only needs 2 fields (Path and Content)
When rendering and processing the form
Then only include Path and Content (rename from Markdown field)
And provide an example Path of `hello-world.md`
And proved an example Content in the example below.

Given the /anttp-0/multipart/archive/ endpoint expects an immutable address (rather than a name)
When adding a new article
Then first resolve the name to an immutable address by calling GET /anttp-0/pnr/{name} to get the pointer
And keep the 'PNR response' in a variable
And get the value of `records[""].address` returned in the JSON response as the immutable address
And add `accept: application/json` header

Given the create route adds a new article to an existing blog
When adding a new article
Then ensure the `x-store-type` is set to 'disk' when PUT to /anttp-0/multipart/archive/{address}/{path}
And use the immutable address from "content" above as the {address}
And keep the 'address' field in the JSON response as the 'updated immutable address' for the blog
And add `accept: application/json` header

Given the 'updated immutable address' for the blog is returned after creating an article
When an article has been added successfully
Then update the pointer to resolve from the blog 'name' to the 'updated immutable address'
And make a PUT request to /anttp-0/pnr/{name} with the body set to 'PNR response', but with `records[""].address` set to the 'updated immutable address'
And ensure the `x-store-type` is set to 'disk' when PUT to /anttp-0/pnr/{name}
And add `accept: application/json` header
